# Parity check: JavaScript text front-end vs. Python

`docs/js/front-native.js` (with `docs/js/trnorm/`) is a JavaScript port of `docs/py/ahenk_front.py` and `docs/py/trnorm/`. The voice depends on the spoken form, so the port must give exactly what the Python gives (the spoken string and every piece's `text`, `pause`, `ids`, `cw`, `wstart`) and must throw wherever the Python raises. These scripts check that on a large corpus. Generated data (corpora, references, reports) belongs outside the repo.

```sh
bash tools/parity/run.sh DIR [FUZZ_N] [SEED]   # corpus + reference + check; exit 1 if anything differs
node tools/parity/check.mjs DIR                # after a change to the JS port: re-check only
```

- `corpus.py --out DIR [--fuzz N] [--seed S] [--fuzz-only]` writes `DIR/corpus.jsonl` (`{"id", "text", "speed"}`): every string in the upstream normalizer and web-demo tests, the TTS benchmark sets, the VoxCPM text bank, the fixture documents (paragraphs, sentences, 12-paragraph windows, small documents whole), `extra_cases.txt` (one case per line, `\n`, `\t`, `\uXXXX`, `\UXXXXXXXX` escapes; `py: EXPR` for a text too long to write out, a Python expression of str literals, `+` and `*` such as `py: '-' * 40000`; `speed=JSON: TEXT` for a case with a speed of its own, such as `speed=0: 12` or `speed="1e-9": ...`), and N seeded fuzz cases. The fuzz mixes realistic sentences with nasty input: numbers of every shape and size (past `int()`'s 4300-digit limit too), dates, times, money, percentages, units, phones, IBANs, plates, URLs and e-mails, every lexicon entry in context (all 1450 are reached by `--fuzz 20000`), ALL-CAPS headlines, clitics, Unicode digits, whitespace and invisible characters, combining marks, dotted and dotless i, ligatures, emoji, mixed scripts, lone surrogates, chunk-boundary lengths, astral characters inside the normalizer's context windows, Python's `$` before a final newline, and characters that Unicode 15.1 and 16.0 added (unassigned for Pyodide's Python, letters, digits, case pairs and compositions for a current browser). The id names the source before the first `:` (`fuzz.<generator>` for fuzz cases). The same arguments always give the same file.
- `pyodide_ref.mjs DIR [--out FILE] [--compare FILE]` runs the Python in Pyodide 0.27.7, loaded through `docs/js/front.js` as the site does. `reference.py DIR [--out FILE]` runs it in CPython. Both write `{"id", "spoken", "pieces"}` or `{"id", "error": "<ExceptionType>"}` per case, plus `<file>.meta.json`. A speed under 1/180 makes `prepare()` loop forever on any text with a letter; `never_returns.py` has `chunk()` raise there first, recorded as `"error": "NeverReturns"` (the JS port throws a `RuntimeError` there by design, and `check.mjs` expects that).
- `check.mjs DIR [--max-examples K] [--ref FILE] [--only REGEX] [--twice] [--module PATH]` runs the port (or another copy of it) on the corpus and files each difference under the first component that differs: `spoken`, `piece_text`, `pause`, `ids`, `cw`, `wstart`, `piece_count`, `shape` (key order, types), `js_threw`, `js_missing_throw`, `error_type` (both raise, but the JS error's `name` is not the Python exception type) (`unstable` with `--twice`). It writes `DIR/report.json` (examples with the input and both values, counts per source, the slowest cases) and prints a one-line summary. Cases and references are paired by id, so a corpus that repeats an id is refused (exit 2).
- `adversarial.py --out DIR --kind KIND [--n N] [--seed S]` writes a corpus in the same format from inputs built to break a translation rather than to look like text: `chars` (short strings of the characters and fragments the regexes care about, packed without spaces), `long` (the same, longer, at speeds down to 1/180), `surrogates` (lone surrogates around characters the normalizer deletes: Python keeps two of them as two code points, a JS string would join them), `speeds` (speed as a string, the way `float()` reads it) and `big` (a few inputs of N characters). Run `reference.py` (or `pyodide_ref.mjs`) and `check.mjs` on DIR as usual.
- `matchers_check.mjs [N] [SEED]` compares the port's linear matchers with the patterns they stand for, on random strings made of what those patterns care about: Python's URL, e-mail and alnum patterns (and a few others) take O(n²) on long chains such as `1.1.1…`, `a-a-a…` or `ş+ş+…`, so the port finds the same matches without trying every hopeless start (`normalizer.js` argues each one at its definition). Every match must be the same, start, text and groups.
- `str_exhaustive.py DIR` (run it with python3.12) and `str_exhaustive.mjs DIR` compare the str methods the port re-implements (`py.js`: `lower()` with its final sigma rule, `upper()`, `isupper` … `isspace`, and `casing.js`) on every code point. Case data comes from `case_tables.js`, which `gen_case_tables.py` writes from CPython 3.12: an engine's own data is newer (U+1171E is no longer case-ignorable in Unicode 16, ʕ no longer lowercase in Unicode 17, Unicode 16 paired ƛ with a new capital), and the port must read text as Python 3.12 does.
- `api_check.mjs [N] [SEED]` compares the exported `number_to_words` / `ordinal_to_words` with Python's for every kind of argument (a BigInt or safe integer is an int, another number a float, a boolean a bool, a string a str), fixed and random values: the same reading or the same exception type.
- `trnorm_reference.py DIR` (python3.12) and `trnorm_check.mjs DIR` compare the trnorm API itself on a corpus: `normalize`, `normalize_for_eval` and `inverse_normalize` of every case, and `inverse_normalize` of Python's spoken and eval forms of it (ASR-like input). `inverse_normalize` is cubic in a run of number words in Python too, so a call that takes Python more than 20 s is left out. `trnorm/` is also published on its own: ozguradmin/trnorm-js, npm package `@ozgurguler/trnorm`.
- `run.sh` with `FUZZ_ONLY=1` makes a fuzz corpus without another copy of the base cases.

The reference is Pyodide, because that is what the site runs today and CPython 3.13 differs from it. On the non-fuzz sources alone (12,038 cases) CPython 3.13.16 and Pyodide agree. With 3000 fuzz cases added (`--fuzz 3000 --seed 2`, 15,038 cases) they differ on 8 cases, and with `--fuzz 20000 --seed 1` (32,038 cases) on 46, always in the spoken form. Every one of those cases contains a CJK Extension I character (U+2EBF0 to U+2EE5D), which Unicode 15.1 added: CPython 3.13 reads it as a letter (`\w`, `isalpha`), while Pyodide's Python 3.12.7 (Unicode 15.0) leaves it unassigned. CPython 3.12.3 (Unicode 15.0) gave the same results as Pyodide on every case, so `REF=cpython PYTHON=python3.12 bash tools/parity/run.sh ...` is a faster stand-in. `run.sh` takes Pyodide from `PYODIDE_DIR` (`npm install pyodide@0.27.7` somewhere outside the repo) and the model vocabulary from `AHENK_VOCAB`. `front_exhaustive.*` and `gen_unassigned.py` are the port's own per-code-point checks and table generator.

Engines: the port is checked in Node (V8) and, as a classic-script bundle of `front-native.js`, in the JavaScriptCore of WebKit builds from Safari 16.4 to 27.2. Two JavaScriptCore bugs shape it: before WebKit 2370 a lookbehind with a class or `\p{}` escape does not see an astral character before it (`py.js` `lb`/`nlb` step back with `.` and test the class with a lookahead), and Safari 26.0 to 26.5 decode a character of U+D800–U+DBFF or U+F800–U+FBFF followed by one of U+FC00–U+FFFF as one code point in a u-flag pattern (`ﬁ５`, a ligature before a fullwidth digit). The port keeps lone surrogates away from u-flag patterns, and in such an engine it throws an `EngineError` for a text that still holds such a pair, so the worker hands that text to the Python.
