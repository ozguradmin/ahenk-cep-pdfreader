# Parity check: JavaScript text front-end vs. Python

`docs/js/front-native.js` (with `docs/js/trnorm/`) is a JavaScript port of `docs/py/ahenk_front.py` and `docs/py/trnorm/`. The voice depends on the spoken form, so the port must give exactly what the Python gives (the spoken string and every piece's `text`, `pause`, `ids`, `cw`, `wstart`) and must throw wherever the Python raises. These scripts check that on a large corpus. Generated data (corpora, references, reports) belongs outside the repo.

```sh
bash tools/parity/run.sh DIR [FUZZ_N] [SEED]   # corpus + reference + check; exit 1 if anything differs
node tools/parity/check.mjs DIR                # after a change to the JS port: re-check only
```

- `corpus.py --out DIR [--fuzz N] [--seed S] [--fuzz-only]` writes `DIR/corpus.jsonl` (`{"id", "text", "speed"}`): every string in the upstream normalizer and web-demo tests, the TTS benchmark sets, the VoxCPM text bank, the fixture documents (paragraphs, sentences, 12-paragraph windows, small documents whole), `extra_cases.txt` (one case per line, `\n`, `\t`, `\uXXXX` escapes), and N seeded fuzz cases. The fuzz mixes realistic sentences with nasty input: numbers of every shape and size (past `int()`'s 4300-digit limit too), dates, times, money, percentages, units, phones, IBANs, plates, URLs and e-mails, every lexicon entry in context (all 1450 are reached by `--fuzz 20000`), ALL-CAPS headlines, clitics, Unicode digits, whitespace and invisible characters, combining marks, dotted and dotless i, ligatures, emoji, mixed scripts, lone surrogates, chunk-boundary lengths, astral characters inside the normalizer's context windows, Python's `$` before a final newline, and characters that Unicode 15.1 and 16.0 added (unassigned for Pyodide's Python, letters, digits, case pairs and compositions for a current browser). The id names the source before the first `:` (`fuzz.<generator>` for fuzz cases). The same arguments always give the same file.
- `pyodide_ref.mjs DIR [--out FILE] [--compare FILE]` runs the Python in Pyodide 0.27.7, loaded through `docs/js/front.js` as the site does. `reference.py DIR [--out FILE]` runs it in CPython. Both write `{"id", "spoken", "pieces"}` or `{"id", "error": "<ExceptionType>"}` per case, plus `<file>.meta.json`.
- `check.mjs DIR [--max-examples K] [--ref FILE] [--only REGEX] [--twice]` runs the port on the corpus and files each difference under the first component that differs: `spoken`, `piece_text`, `pause`, `ids`, `cw`, `wstart`, `piece_count`, `shape` (key order, types), `js_threw`, `js_missing_throw`, `error_type` (both raise, but the JS error's `name` is not the Python exception type) (`unstable` with `--twice`). It writes `DIR/report.json` (examples with the input and both values, counts per source, the slowest cases) and prints a one-line summary.
- `adversarial.py --out DIR --kind KIND [--n N] [--seed S]` writes a corpus in the same format from inputs built to break a translation rather than to look like text: `chars` (short strings of the characters and fragments the regexes care about, packed without spaces), `long` (the same, longer, at speeds down to 1/180), `surrogates` (lone surrogates around characters the normalizer deletes: Python keeps two of them as two code points, a JS string would join them), `speeds` (speed as a string, the way `float()` reads it) and `big` (a few inputs of N characters). Run `reference.py` (or `pyodide_ref.mjs`) and `check.mjs` on DIR as usual.

The reference is Pyodide, because that is what the site runs today and CPython 3.13 differs from it. On the non-fuzz sources alone (12,038 cases) CPython 3.13.16 and Pyodide agree. With 3000 fuzz cases added (`--fuzz 3000 --seed 2`, 15,038 cases) they differ on 8 cases, and with `--fuzz 20000 --seed 1` (32,038 cases) on 46, always in the spoken form. Every one of those cases contains a CJK Extension I character (U+2EBF0 to U+2EE5D), which Unicode 15.1 added: CPython 3.13 reads it as a letter (`\w`, `isalpha`), while Pyodide's Python 3.12.7 (Unicode 15.0) leaves it unassigned. CPython 3.12.3 (Unicode 15.0) gave the same results as Pyodide on every case, so `REF=cpython PYTHON=python3.12 bash tools/parity/run.sh ...` is a faster stand-in. `run.sh` takes Pyodide from `PYODIDE_DIR` (`npm install pyodide@0.27.7` somewhere outside the repo) and the model vocabulary from `AHENK_VOCAB`. `front_exhaustive.*` and `gen_unassigned.py` are the port's own per-code-point checks and table generator.
